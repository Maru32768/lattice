# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Lattice is a local-first Windows desktop app (Tauri 2 + React 19) for collecting, reading, translating and searching technical articles. User docs: `README.md`, `docs/guide.md`. Developer docs: `docs/development.md`. Design decisions per feature (Japanese): `docs/design-review.md`; planned work: `docs/roadmap.md`.

## Commands

Node and Rust versions are pinned in `mise.toml`; run every tool through `mise exec --` (or a `mise run` task).

```bash
mise run dev                  # app with hot reload (uses %APPDATA%\Lattice Dev)
mise run lint                 # overlay build, rustfmt --check, clippy -D warnings, oxlint, prettier --check, React Compiler check
mise run test                 # lint + cargo test --workspace + npm test + npm run build (typecheck incl. tests)
mise run e2e                  # Playwright over the mock backend (needs `npx playwright install chromium` once)
mise exec -- npm run format   # Prettier
mise exec -- npm run tauri build
```

Single tests:

```bash
mise exec -- cargo test -p lattice-core <name_filter>
mise exec -- node --test src/chat/chat.test.ts          # frontend unit tests are node:test on .ts files
mise exec -- npx playwright test e2e/reader.spec.ts -g "<title>"
```

- `src-tauri` embeds `src-tauri/overlay-dist/overlay.js` via `include_str!`, so run `npm run build:overlay` before building/clippy-ing the Tauri crate (`mise run lint` and `npm run dev` do it).
- E2E specs read the Japanese UI (locale `ja-JP`); only `e2e/english.spec.ts` runs in English. Set `E2E_PORT` when several checkouts run the suite at once.
- If `lattice.exe` is running it locks the build output; stopping it is fine.
- Debug app and CLI builds use `%APPDATA%\Lattice Dev`; release builds use `%APPDATA%\Lattice`. Release and development libraries remain separate; older identifier-based folders are not migrated automatically. Saved data-folder selections, WebView2 profiles, caches, and logs are separate. GUI logs use `%LOCALAPPDATA%\Lattice Dev\logs` in debug and `%LOCALAPPDATA%\Lattice\logs` in release, including with custom libraries; old logs are preserved. Tauri identifiers use dev.marulabs.lattice; browser profiles are separate for each build. Portable logs stay in `data/logs`. Portable mode and CLI `--data-dir` overrides use their selected locations.

## Architecture

Cargo workspace with three crates plus the React frontend:

- **`crates/lattice-core`** — all domain logic, no Tauri dependency. `store.rs` is the concrete SQLite store (system of record). `jobs.rs` runs a durable job queue stored in SQLite: separate runners for LLM jobs, local jobs (embeddings) and network jobs (`LLM_JOBS` / `LOCAL_JOBS` / `NET_JOBS`), so a long translation queue never delays importing. Each domain module (`translate`, `summarize`, `classify`, `quiz`, `vocab`, `relevance`, `feed_filter`, `ingest`, `images`, `favicons`, `embed`) owns its `JOB_TYPE`.
- **LLM boundary** — `llm.rs` defines `LlmProvider`; adapters (`claude.rs`/`codex.rs` drive the user's logged-in CLIs, `openai.rs`/`gemini.rs`/`anthropic.rs` are APIs) only move JSON in and out against a JSON schema. `chain.rs` is a runtime-swappable fallback chain of up to three (provider, model) entries with cooldown. Domain code builds prompts and validates results.
- **`crates/lattice-cli`** — `lattice-cli` and its MCP server (`mcp.rs`), built on `lattice-core` alone.
- **`src-tauri`** — `lib.rs` holds the Tauri commands and starts the job runners; `browser.rs` is the in-app browser (child webviews `browser-<tab>`), `renderer.rs` a hidden webview that renders JS-built pages, `popout.rs`/`tabdrag.rs` the pop-out windows and cross-window tab dragging. Backend → UI updates are Tauri events (`article-changed`, `feeds-changed`, `vocab-changed`, `favicon-changed`, …).
- **`src`** — React frontend, one folder per feature; `app/` is the shell (state hooks `use*.ts`), `layout/` the tabs/split panes, `api.ts` the typed IPC client mirroring the Rust serde types. `src/overlay` is a separate IIFE bundle (`vite.overlay.config.ts`) injected into remote pages in the in-app browser.

### Adding or changing a Tauri command

A command touches several places, and tests catch the misses:

1. `#[tauri::command]` in `src-tauri/src/lib.rs` and its `invoke_handler` entry. Commands that touch the store must be `async` or `command(async)`: sync commands run on the UI thread and freeze the window while a job holds the store lock.
2. The command name in `COMMANDS` in `src-tauri/build.rs` (generates `permissions/autogenerated/*.toml`).
3. `allow-<name>` in `src-tauri/capabilities/default.json` (app UI). Remote pages (`capabilities/browser.json`) get only the `overlay_*` commands — never grant them more.
4. The wrapper in `src/api.ts`, and a handler in `e2e/mock.ts` (`e2e/commands.test.ts` fails otherwise).

## Conventions

- **UI text** lives in `src/i18n/ja.ts` (key source) and `src/i18n/en.ts` (must match). A Japanese literal in UI code fails `src/i18n/literals.test.ts`.
- **Backend errors/messages that reach the UI** are codes: `msg!("code", name = value)` in Rust, with a `be.<code>` entry in both catalogs (`src/i18n/backend.test.ts`). They travel as JSON strings through `Result<_, String>` and `last_error` columns.
- **Untrusted content.** Article text, pages and feed data are untrusted: the UI renders them as text only, and LLM providers never get tools (the CLI adapters disable tools, MCP and settings and run in an empty directory).
- **Migrations** in `store.rs` (`MIGRATIONS`) are append-only; a migration test finds its migration by content, not by index. Credential settings use the `secret.` prefix and are excluded from backups.
- **React Compiler** must compile every component (`scripts/react-compiler.mjs`); it silently skips constructs like try/finally, so restructure rather than suppress.
- **Formatting:** 160-column lines in both rustfmt and Prettier; rustfmt puts every `if/else` and `let … else` block on its own lines; every TS block is braced. Workspace clippy denies `unwrap_used`, `todo`, `dbg_macro` etc. outside tests; `#[allow]` needs a `reason`.
- **Japanese text** (docs and `src/i18n/ja.ts`) uses half-width parentheses `()`, with a space between them and adjacent text as with alphanumerics: `残す世代数 (既定 30) を超えると`. UI labels quoted in the docs match the catalog exactly.
- Comments explain *why* (constraints, past bugs), often citing roadmap ids like `F3`, `G51` or numbered sections in `docs/design-review.md`. A deliberate deferral is marked `// shortcut: …`.
- The app version is shared by `package.json` and the workspace `Cargo.toml`; bump with `npm run bump -- <x.y.z>`. Releases: `docs/release.md`.
