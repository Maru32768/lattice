## はじめに

### 画面の構成

メインウィンドウには、左から次の領域が並びます。

| 領域 | 内容 |
|---|---|
| ナビ (左のサイドバー) | 記事の一覧の切り替え (「ライブラリ」「グループ」「ジャンル」「ソース」)、「ツール」 (「対話」「今日の復習」「単語帳」「処理状況」「一括インポート」)、いちばん下に「設定」 |
| 記事一覧 | ナビで選んだ一覧の記事。上に絞り込みと並び順の操作がある |
| 文書エリア | 記事や Web ページをタブで開く場所。複数のペインに分割できる |
| 対話ペイン | ナビの「対話」を押すと右端に開く |

いちばん上のタイトルバーには、アプリの中で移動した場所を戻る・進むボタン (‹ ›) と、コマンドパレットを開く箱 (「検索・コマンド・URL」、`Ctrl+K`) があります。

- 領域の境目をドラッグすると幅が変わります。境目をダブルクリックすると元の幅に戻ります。幅は次の起動でも保たれます。
- ナビは上端のボタンで、記事一覧は一覧のボタンで閉じられます。閉じた記事一覧は細い帯になり、同じボタンでまた開きます。
- 「フィードを管理」「処理状況」「一括インポート」「単語帳」「今日の復習」の画面は、記事一覧と文書エリアの場所に表示されます。「設定」はナビの場所も使います。`Esc` でライブラリの画面に戻ります。

ライブラリが空のときは、文書エリアに「最初の記事を入れる」が出ます。そこから URL の貼り付け・フィードの登録・一括インポート・Markdown の取り込みに進めます。

### AI プロバイダを設定する

翻訳・要約・分類・重要度・理解度チェック・単語の意味・フィードの LLM 判定・対話は、AI プロバイダに文章を送って処理します。これらを使うには、「設定 › AI プロバイダ」でプロバイダを 1 つ以上設定してください。記事の保存・閲覧・全文検索は、設定しなくても使えます。

使えるプロバイダは次のとおりです。

| プロバイダ | 必要なもの |
|---|---|
| Claude CLI | `claude` コマンドをインストールし、ログインしておく |
| Codex CLI | `codex` コマンドをインストールし、ログインしておく |
| OpenAI API | API キー |
| Gemini API | API キー |
| Anthropic API | API キー |

**段の並び。** プロバイダは最大 3 段まで並べられます。Lattice はふだん 1 段目を使い、呼び出しが失敗したとき (usage limit に達したときなど) は次の段で同じ処理をやり直します。失敗した段は、その後 5 分間は後回しにします。ほかの段が代わりに処理したときも、失敗した段とその理由 (CLI がインストールされていないなど) を「設定 › AI プロバイダ」と「処理状況」に表示します。段の順番はドラッグで変えます。キーボードでは、`Space` で段を持ち上げ、矢印キーで動かし、もう一度 `Space` で置きます。

**モデルと effort。** 段ごとに、プロバイダ・モデル・effort を選びます。effort は、モデルがどれだけ時間をかけて考えるかの設定です。上げると品質が上がることがありますが、遅くなり、費用も増えます。大量の記事を翻訳するなら、速いモデルと低い effort がおすすめです。一覧にないモデルは「その他 (モデル ID を入力)」で ID を入力して使えます。モデルが対応していない effort を選ぶと、その段の呼び出しは失敗し、次の段に進みます。

**API キー。** API のプロバイダは、「API キー」の欄にキーを入力します。キーは Lattice のデータベースに保存し、保存した後は画面に表示しません。バックアップとエクスポートにも含めません。キーを保存していないときは、環境変数 `OPENAI_API_KEY`・`GEMINI_API_KEY`・`ANTHROPIC_API_KEY` を読みます。

どの機能で何を送るかは、[AI プロバイダに送るもの](#ai-プロバイダに送るもの)にまとめています。

### 「自分について」を書く

「設定 › 要約・対話」の「自分について」に、自分の仕事・関心・前提にしてよい知識などを書いておくと、AI の出力がそれに合わせたものになります。2,000 文字まで書けます。反映されるのは次の機能です。

- 要約と、対話の回答
- 理解度チェックの問題
- 記事の[重要度](#重要度) (「自分について」が空のときは判定しません)
- フィードの LLM 判定

## 記事を集める

Lattice は、記事ごとに本文・画像・取得した元の HTML を保存します。元のページが消えたり変わったりしても、保存した記事は読めます。Lattice では、保存した記事の集まりを Index と呼びます。

### URL を保存する

1. `Ctrl+K` でコマンドパレットを開きます。
2. URL を貼り付けます。
3. 「Index に追加 (取り込み)」を選ぶか、`Ctrl+Enter` を押します。

ページの取得はバックグラウンドで行います。

URL を貼ったパレットには、ほかに次の項目が出ます。

- 「Page で開く」: 保存せずに、アプリ内ブラウザでページを開きます。
- 「フィードを検出して登録」: そのサイトのフィードを探して登録します。
- 「Reader で開く」: すでに保存した URL のとき、保存した記事を開きます。
- 一覧でグループを開いているときは、保存と同時にそのグループに入れる項目も出ます。

保存済みかどうかは、`utm_source` のようなトラッキング用のパラメータを除いた URL で判定します。そのため、パラメータだけが違う URL を貼っても、新しく保存せずに既存の記事を開きます。取得に失敗した記事の URL をもう一度保存すると、取得をやり直します。

### 閲覧中のページを保存する

Page 表示 (アプリ内ブラウザ) で見ているページを保存するには、ツールバーの「Index に追加」を押します。ブラウザが表示したままの内容を保存するので、JavaScript で描画するページや、ログインしないと見られないページも欠けずに入ります。保存するとツールバーに「Index 済み」と出て、Reader 表示・タグ・ジャンル・お気に入りが使えるようになります。

### ファイルを取り込む

ナビの「ツール」から「一括インポート」を開きます。画面には「URL 一覧」「Markdown」「PDF」の 3 つのタブがあります。タブの上の「グループ」の欄でグループを選ぶと、取り込んだ記事をそのグループに入れます。

**URL 一覧。** URL を含むテキストなら、形式を問わず読み込みます。URL を並べたテキスト、ブラウザから書き出したブックマーク (HTML)、CSV、JSON、ほかの read-later サービスのエクスポートなどです。テキストを貼るかファイルを選んで、「インポート」を押します。取得はバックグラウンドで行い、新規・保存済み・無効な URL の件数を表示します。途中で取得に失敗したページがあっても、残りの取り込みは続けます。

**Markdown。** Markdown のファイル 1 つ、または貼り付けたテキストを、1 つの記事にします。

- タイトルは最初のレベル 1 の見出し (`# `) です。見出しがなければ、ファイル名か最初の行を使います。
- `https://` などの Web の URL で書かれた画像は、ダウンロードして保存します。相対パスの画像は、ファイルから取り込んだときだけ、そのファイルのあるフォルダから読み込みます。
- HTML のタグは取り込みません。
- 元になる Web ページがないので、Page 表示は使えません。

**PDF。** 論文などの PDF を 1 つの記事にします。PDF の中の文字を読み、2 段組の読む順番・見出し・図表のキャプション・参考文献を組み立て直します。文字のデータがない PDF (スキャンした画像だけの PDF) は取り込めません。

arXiv の `…/pdf/…` のような PDF の URL は、このタブを使わなくても、普通の URL と同じように保存できます。フィードに含まれる PDF も取り込めます。

### フィードを登録する

RSS と Atom のフィードを登録すると、新しい記事を自動で取り込みます。ナビの「ソース」の横の「管理」か、パレットの「フィードを管理」で、フィードの管理画面を開きます。

#### 登録する

サイトか記事の URL を入力して「検出」を押すと、Lattice がフィードを探します。

1. 入力した URL がフィードそのものなら、それを候補にします。
2. そうでなければ、ページの中にあるフィードへのリンクを探します。
3. それでも見つからなければ、`/feed` や `/rss.xml` のようなよく使われる場所を試します。

候補から 1 つ選び、「登録して最新 20 件を取り込む」を押します。

フィードの URL が分かっているときは、1 行に 1 つずつ貼り付けると、リンクを探さずにまとめて登録します。

#### 更新のタイミング

Lattice は、起動したときと、その後 30 分ごとに、すべてのフィードの新着を確認します。登録した直後は最新の 20 件を取り込み、その後は新しく出た記事だけを取り込みます。「すべて更新」を押すと、今すぐ確認します。

管理画面の各フィードの行には、状態・最終更新・未読数と記事数が出ます。「記事を見る →」で、そのフィードの記事の一覧を開きます。

フィードを削除しても、取り込んだ記事は残ります。残った記事はナビの「手動追加」に移ります。

#### フォルダ

フォルダは、フィードをまとめる入れ物です。チャンネルごとに RSS を出すサービスのように、同じサイトのフィードが多いときに便利です。1 つのフィードが入るフォルダは 1 つだけで、フォルダの中にフォルダは作れません。

- **作る。** 管理画面の「フォルダ」の欄に名前を入れて「作成」を押します。名前の変更・並べ替え・削除もここでできます。
- **フィードを入れる。** フィードの行でフォルダを選びます。複数のフィードにチェックを付けて「フォルダへ移動…」を押すと、まとめて移せます。
- **登録と同時に入れる。** 登録する前に、入力欄の横のフォルダのメニュー (初めは「フォルダなし」) で選びます。このメニューは、フォルダが 1 つ以上あるときだけ出ます。
- **ナビでの表示。** フォルダは開閉できる行になり、数字は中のフィードの未読数の合計です。フォルダを押すと、中のすべてのフィードの記事が一覧に出ます。右クリックか ⋯ で、名前の変更と削除ができます。フォルダを削除しても、中のフィードは残ります。

#### 並び順

フィードは、フォルダの中と、どのフォルダにも入っていないフィードの中で、それぞれ自分で並べた順を保ちます。ナビ・管理画面・パレット・範囲の選択・OPML の書き出し・CLI のどこでも、この順で並びます。

ナビでは、ドラッグで並べ替えます。

- フィードを別のフィードの上で離すと、その位置に入ります。別のフォルダのフィードの上でもかまいません。
- フォルダの行の上で離すと、そのフォルダの最後に入ります。閉じたフォルダでも同じです。
- フォルダから出すには、フォルダに入っていないフィードの間で離します。すべてのフィードがフォルダに入っているときは、ドラッグしている間だけ、いちばん下に「ここに置くとフォルダから出します」という枠が出ます。
- フォルダの行をドラッグすると、フォルダの順番が変わります。中のフィードも一緒に動きます。

ドラッグしたときだけ並びが変わります。短くクリックしたときは、これまでどおりフィードやフォルダを開きます。

キーボードでは、フィードかフォルダの行にフォーカスを置いて `Alt+↑` と `Alt+↓` を押すと、1 つずつ動きます。フォルダの先頭や末尾を越えたフィードは隣のフォルダに入り、そのフォルダが閉じていれば開きます。

管理画面では、フィードの表と「フォルダ」の欄の各行の ⋮⋮ をドラッグして並べ替えます。別のフォルダのフィードの上で離すと、そのフォルダに移ります。キーボードでは、⋮⋮ にフォーカスを置いて `Space` で持ち上げ、矢印キーで動かし、もう一度 `Space` で置きます。

管理画面でも、フィードはフォルダごとに同じ順で並びます。行ごとの ↑ と ↓ のボタンで動かせます。

#### 名前とアイコン

フィードの行の「編集」で、「表示名」と「アイコン」を変えられます。アイコンには PNG・JPEG・GIF・WebP・SVG・ICO の画像 (1 MB まで) を使えます。アイコンを設定しなければ、サイトのアイコンを表示します。「元に戻す」でフィード本来の名前に、「サイトのアイコンに戻す」でサイトのアイコンに戻ります。

#### 取り込みフィルタ

フィードの新着のうち、どれを取り込むかを決める仕組みです。フィルタは 2 か所で設定できます。

- 全体のフィルタ: 「設定 › 取り込みフィルタ」。すべてのフィードに効きます。
- フィードごとのフィルタ: フィードの行の「編集」の中。

新着の記事は、両方のフィルタを通ったものだけを取り込みます。フィルタには次の条件を組み合わせられます。

- **ルール。** 「タイトル」「URL」「著者」「カテゴリ」「ドメイン」「言語」のどれかに、キーワードか正規表現を当てます。大文字と小文字は区別しません。ルールには除くルールと含むルールがあります。除くルールのどれか 1 つにでも合う記事は取り込みません。含むルールが 1 つ以上あるときは、そのどれかに合う記事だけを取り込みます。
- **「本文の最短文字数」。** 本文がこの文字数より短い記事を除きます。記事の本文をフィードに載せているサイトにだけ効きます。
- **LLM での判定。** 「ルールを通った記事を LLM で判定する」をオンにすると、ルールを通った記事を AI プロバイダに判定させます。送るのは、記事のタイトル・URL・抜粋と、「自分について」、「取り込む記事の指示」です。「重要度の下限」を選ぶと、AI が付けた 1〜5 の点数がそれ以上の記事を取り込みます。AI の呼び出しに失敗した記事は、取りこぼさないように取り込み、フィードに失敗の理由を表示します。

フィルタで除いた記事は、「除外された記事」に除いた理由と一緒に残ります。

- 「取り込む」で、その記事を 1 件ずつ取り込めます。
- 「このルールを外す」で、その記事を除いたルールを削除します。
- ルールを変えても、すでに除外した記事は自動では取り込みません。今のルールで判定し直すには「除外分を再評価」を押します。

#### OPML

ほかのフィードリーダーとの間でフィードを移すときに使います。

- 「OPML を読み込む」で、OPML ファイルのフィードを登録します。フィードを囲む outline 要素は、フォルダとして登録します。
- 「OPML に書き出す」で、フォルダを含めたフィードの一覧を `exports` フォルダに書き出します。

### 本文がうまく取れないページ

ページによっては、取得した直後の HTML に本文がほとんどなく、JavaScript を実行してはじめて本文が表示されます。こうしたページを保存すると、本文が空か 300 文字未満になり、記事一覧に「抽出失敗」か「本文が短い」と表示されます。

**自動で描画し直す。** 「設定 › 取り込み・JS 描画」の「JS ページを自動で描画」がオンなら、Lattice は表に出ないブラウザでそのページを開いて描画し、本文を取り込み直します。1 件あたり最大で 20 秒ほどかかります。403 や 429 のように、サイトが取得を断ったものの、ブラウザからなら読める可能性があるエラーのときも、同じように描画を試します。描画した結果で記事を置き換えるのは、本文が前より増えたときだけです。

**手で取り込み直す。** 記事の ⋯ メニューの「描画して取り込み直す」で、同じ処理を手で実行できます。Page 表示では「表示中のページで取り込み直す」も使えます。こちらは今画面に見えているページから取り込むので、ログインした後の内容も入ります。

**フィードの本文を使う。** ブラウザ以外からの取得を断るサイトもあります。そのサイトのフィードが記事の本文を載せていれば、Lattice はフィードの本文で記事を作り、Reader にそのことを表示します。Reader の「再試行」で、元のページの取得をやり直せます。

## 記事を読む

### Reader 表示と Page 表示

保存した記事は、2 つの表示で読めます。ツールバーの左端の「Reader」と「Page」で切り替えるか、`v` を押します。

- **Reader 表示**は、ページから取り出した本文を、見出し・リスト・コード・表・保存した画像と一緒に表示します。表示のために Web にアクセスすることはありません。
- **Page 表示**は、アプリ内ブラウザで元の Web ページを表示します。翻訳と単語の登録は、Reader 表示と同じように使えます。

取り込んだ Markdown と PDF のファイルには、元の Web ページがないので Page 表示はありません。URL から保存した PDF は、Page 表示ではブラウザの PDF ビューアで開きます。

**ツールバー。** 2 つの表示のツールバーの右端には、同じボタンが並びます: 「お気に入り」「既読にする」「質問」「理解度チェック」「メモ」、フォーカスモード、⋯ メニュー。⋯ メニューには次の操作があります。

- 「再抽出」: 保存してある HTML・PDF・Markdown から、ネットワークに接続せずに記事を作り直します。Lattice の更新で本文の取り出し方がよくなったときに使います。
- 取り込み直す操作 ([本文がうまく取れないページ](#本文がうまく取れないページ)を参照)
- 「自動分類」「訳し直す」「要約を作成」「URL をコピー」「Index から削除…」

**アプリ内ブラウザ。** Page 表示のツールバーには、戻る・進む・再読み込み・「ホーム (検索エンジン)」のボタンがあります。URL の部分を押すと編集でき、`Enter` で開き、`Esc` で編集をやめます。URL でない語を入力すると、「設定 › ブラウザ」で選んだ検索エンジンで検索します。サイトへのログイン状態は、Lattice を終了しても残ります。

### 原文・訳文・混在を切り替える

「Reader」「Page」のすぐ右にある切り替えで、本文をどの言語で表示するかを選びます。

- 「原文」: 書かれたままの本文です。
- 「訳文」: 翻訳した本文です。
- 「混在」: 一部の段落だけを訳文にします。横のパーセントは、訳文にする段落の割合です。`[` で 10% 下げ、`]` で 10% 上げます。

翻訳の向きは記事の言語で決まります。日本語の記事は英語に、それ以外の言語の記事は日本語に訳します。アプリの表示言語を英語にしても、この向きは変わりません。

「混在」で訳文にする段落は、次のように選びます。

- Reader 表示では、記事全体に均等に散らばるように選びます。
- Page 表示では、ページのアドレスと本文から決めます。そのため、同じページはいつ開いても同じ段落が訳文になります。

この選択は、Reader 表示と Page 表示で別々に保存されます。一度選ぶと、変えるまですべての記事 (Page 表示ではすべてのページ) に効きます。Lattice を起動した直後は、Reader 表示が「混在」70%、Page 表示が「原文」です。

### 1 つの段落だけ言語を切り替える

訳してある段落にポインタを少しの間乗せると、もう一方の言語の文が吹き出しで出ます。吹き出しか、段落の端の小さな印を押すと、その段落だけ表示する言語が切り替わります。キーボードでは、段落にフォーカスを移して `Enter` を押します。

Page 表示では、同じ吹き出しが段落ではなく文ごとに出ます。

### 記事を翻訳する

Reader 表示のツールバーに、翻訳の進み具合が出ます (例: 「翻訳 12/40」)。

- **自動で始める。** 「表示を切り替えたら自動で翻訳」がオン (既定) なら、「混在」か「訳文」に切り替えたときに、まだ訳していない記事の翻訳が始まります。
- **表示中の記事が先。** 表示している記事 (各ペインの手前のタブ) の翻訳・要約・理解度チェックは、待機中の処理の後ろに並ばず、専用の枠ですぐに始まります。ほかの記事の処理が実行中でも待ちません。
- **手で始める。** 「翻訳する」を押します。一部だけ訳してある記事では「残りを翻訳」が出て、まだ訳していない段落を訳します。ボタンにポインタを乗せると、どの言語に訳すかが出ます。
- **訳し直す。** 「訳し直す」は、この記事の訳文を捨てて、今のプロバイダと設定で訳し直します。1 段落でも訳してあれば ⋯ メニューに、全部訳してあればツールバーにも出ます。訳した段落が 50 を超える記事では、実行前に確認があります。この記事の翻訳が実行中のときは使えません。
- **失敗したとき。** ツールバーに「失敗」・次に自動で再試行する時刻・「再試行」のボタンが出て、本文の上にエラーの内容が出ます。訳し終えた段落は残るので、再試行では残りの段落だけを送ります。

**訳文の共有。** 訳文は段落の本文ごとに保存します。Page 表示で訳した段落は Reader 表示でも訳してあり、その逆も同じです。同じ段落を含むほかの記事やページも、その訳文を使います。そのため、「訳し直す」をすると、同じ段落を持つほかの記事やページの訳文も新しくなります。

**Page 表示の翻訳。** Page 表示で「混在」か「訳文」を選ぶと、表示中のページをその場で訳します。すでに訳先の言語で書かれている段落は、AI プロバイダに送りません。

**翻訳の設定。** 「設定 › 翻訳」で次の項目を変えられます。どの項目も、Reader 表示と Page 表示の翻訳の両方に効きます。

| 設定 | 内容 |
|---|---|
| 「表示を切り替えたら自動で翻訳」 | 「混在」か「訳文」に切り替えたときに翻訳を始めます。既定はオン。この PC だけの設定です。 |
| 「保存した記事を自動で翻訳」 | 記事を保存したらすぐに翻訳を始めます。保存するたびに AI プロバイダを使うので、既定はオフです。表示言語で書かれた記事 (表示言語が日本語なら日本語の記事) は訳しません。 |
| 「表示言語の記事も自動翻訳する」 | 「保存した記事を自動で翻訳」がオンのとき、表示言語で書かれた記事ももう一方の言語に訳します (表示言語が日本語なら、日本語の記事を英語に)。既定はオフ。 |
| 「並列実行数」 | 翻訳で、AI プロバイダへの呼び出しを同時にいくつまで実行するかです (1〜8、既定 3)。いまは 1 つの記事の段落のまとまり (最大 12 段落) を並列に送り、記事は 1 つずつ順に訳します。増やすと早く訳し終わりますが、使用量の上限や API の rate limit に早く当たり、Claude CLI・Codex CLI では同時に動くプロセスが増えます。 |
| 「専門用語を英語のまま残す」 | 日本語に訳すとき、MVCC や write skew のような用語を英語のまま残します。英語に訳すときは、英語圏で定着している用語を使います。既定はオン。 |
| 「追加の指示」 | 翻訳の prompt の末尾に足す指示です。文体や訳語の指定などを書きます。2,000 文字まで。「組み込みの prompt (英語→日本語) を見る」で、指示を足す先の prompt を確認できます。 |

訳文は、「専門用語を英語のまま残す」と「追加の指示」の組み合わせごとに別々に保存します。これらを変えたら、新しい設定で読みたい記事を訳し直してください。設定を元に戻すと、以前の訳文がまた表示されます。

### 要約

Reader 表示の上部の「要約」で「要約を作成」を押すと、AI が記事を要約します。できた要約は 1 行目だけが表示され、押すと全文が開きます。

- 要約には「自分について」の内容が反映されます。
- 「設定 › 要約・対話」の「要約の追加の指示」で、要約だけに足す指示を書けます。
- 要約を作った後で記事の本文か要約の設定が変わると、要約にそのことが表示されます。新しい内容で作り直すには、開いた要約の「作り直す」か、⋯ メニューの「要約を作り直す」を押します。自動で作り直すことはありません。

保存した記事の Page 表示では、ツールバーの「要約」で、同じ要約をページの上に表示できます。

### 検索で一致した箇所を見る

検索結果から記事を開くと、Reader 表示に「一致 1 / 5」のような表示が出ます。横の ↑ と ↓ のボタンで、一致した箇所を順に移動します。

### フォーカスモード

`f` かフォーカスモードのボタンで、ナビと記事一覧をまとめて隠し、本文を広く表示します。もう一度 `f` を押すと元に戻ります。記事一覧を隠していても、`j` と `k` で次・前の記事に移れます。

### 戻る・進む

Lattice は、アプリの中で移動した場所を履歴に残します。記録するのは、開いた画面・設定のセクション・一覧・絞り込み・フォーカスのあるタブの文書です。タイトルバーの ‹ ›、`Alt+←` と `Alt+→`、マウスの戻る・進むボタンで行き来できます。履歴は直近の 50 件まで残ります。

Web ページにキーボードのフォーカスがあるときは、`Alt+←`・`Alt+→`・マウスのボタンは、Lattice の履歴ではなくそのページの履歴を移動します。Page 表示のツールバーの ‹ › は、いつもページの履歴を移動します。

### ページを印刷する

Page 表示で `Ctrl+P` を押すと、Windows の印刷ダイアログが開きます。

## タブ・ペイン・ウィンドウ

### タブ

文書エリアの各ペインにタブの列があり、タブには Reader 表示の記事か Web ページが入ります。

- 一覧・パレット・検索結果・対話の引用から記事を開くと、フォーカスのあるペインで、今表示しているタブの中身を入れ替えます。
- 新しいタブで開くには、`Ctrl` を押しながらクリックするか、中クリックします。
- タブの列の端の「新しいタブ」 (＋) は、検索エンジンのトップページを新しいタブで開きます。`Ctrl+T` はパレットを開き、そこで選んだものを新しいタブで開きます。
- タブを閉じるには、`Ctrl+W`、タブの ×、タブの中クリックのどれかを使います。
- `Ctrl+Tab` と `Ctrl+Shift+Tab` で、隣のタブに切り替えます。
- タブはドラッグで並べ替えられます。

タブとペインの配置は、次に起動したときに元に戻ります。表示していないタブの Web ページは、直近の 3 つまで読み込んだまま残すので、切り替えるとすぐに表示され、スクロール位置も保たれます。それより前のページは、タブに戻ったときに読み込み直します。

### 文書エリアを分割する

- タブの列の「右に分割」か「下に分割」で、フォーカスのあるペインを 2 つに分けます。キーは `Ctrl+\` (右) と `Ctrl+-` (下) です。
- ペインの間の線をドラッグすると、大きさが変わります。線にフォーカスを移して矢印キーでも変えられます。線をダブルクリックすると均等になります。
- 「ペインを閉じる」で、フォーカスのあるペインを閉じます。タブが 1 つもなくなったペインも閉じます。
- タブを別のペインのタブの列にドラッグすると、そのペインに移ります。同じウィンドウの中では、ペインの中央で離すとそのペインに入り、端の近くで離すとそのペインを分割して、新しくできた側に入ります。

フォーカスのあるペインには枠が付きます。ペインの中をクリックするとそのペインにフォーカスが移り、次に開く文書はそこに入ります。

### キーボードでペインを操作する

tmux と同じように、`Ctrl+B` を押してから、続けて次のキーを押します。`Ctrl+B` を押すと、使えるキーの案内が画面に出ます。

| `Ctrl+B` の後のキー | 動作 |
|---|---|
| `←` `→` `↑` `↓` または `h` `j` `k` `l` | その方向のペインへ移動 |
| `o` | 次のペインへ移動 |
| `%` | 右に分割 |
| `"` | 下に分割 |
| `x` | ペインを閉じる |
| `c` `n` `p` | 新しいタブ・次のタブ・前のタブ |
| `z` | フォーカスモード |

### タブを別ウィンドウで開く

タブは、メインウィンドウから出して別のウィンドウ (文書ウィンドウ) で開けます。

- タブの列の「別ウィンドウで開く」か `Ctrl+Shift+N` で、表示中のタブを新しいウィンドウに移します。
- タブをタブの列から上か下に 30 ピクセルほどドラッグすると、新しいウィンドウになり、ポインタについて動きます。ペインを分割したウィンドウでは、ウィンドウの外までドラッグしたときに新しいウィンドウになります。
- ドラッグしたタブを別のウィンドウのタブの列の上で離すと、そのウィンドウに入ります。ドラッグ中に `Esc` を押すと元に戻ります。

文書ウィンドウでは、タブの列がタイトルバーを兼ねます。列の空いた所をドラッグするとウィンドウが動き、ダブルクリックすると最大化します。ペイン・タブ・パレットはウィンドウごとに独立しています。

タブをメインウィンドウに戻すには、「メインウィンドウに戻す」か `Ctrl+Shift+N` を使います。文書ウィンドウを閉じたときも、中のタブはメインウィンドウに戻ります。最後のタブがなくなった文書ウィンドウは閉じます。

タブを別のウィンドウに移すと、Web ページは読み込み直します。戻る・進むの履歴は引き継ぎません。

対話ペインにも「別ウィンドウで開く」があります。「メインウィンドウに戻す」で元の位置に戻ります。対話のウィンドウを閉じた場合は、メインウィンドウに戻さずにそのまま閉じます。

ウィンドウの位置と大きさは保存され、終了したときに開いていたウィンドウは次の起動でも開きます。メインウィンドウを閉じると、Lattice は終了します。

## ライブラリを整理する

### ジャンル・タグ・難易度

記事を保存すると、AI プロバイダがジャンル・タグ (3 つまで)・難易度を付けます。

- **ジャンル**は、Database・Security・Web のような大きな分類です。できるだけ既存のジャンルから選び、合うものがないときだけ新しいジャンルを作ります。
- **難易度**は「入門」「初級」「中級」「上級」「専門」の 5 段階です。その分野を専門にしていない現役のソフトウェアエンジニアにとっての難しさを表します。

分類は、まだ分類していない記事を最大 20 件ずつまとめて、1 回の呼び出しで行います。自動分類をやめるには、「設定 › 自動分類」の「保存した記事を LLM でジャンル分けし、タグを付ける」をオフにします (既定はオン)。同じ画面の「未分類をすべて分類」は、ジャンルか難易度のない記事をすべて分類の待ち行列に入れます。

**手で変える。** Reader 表示のタイトルの下の行で変えられます。

- ジャンルは、入力欄に入力するか候補から選びます。新しい名前を入れると、そのジャンルを作ります。難易度はメニューから選びます。
- 自分で選んだジャンルと難易度は固定され、自動分類で上書きされません。難易度を「未判定」に戻すと、もう一度推定します。
- 「+ タグ」でタグを足し、タグの × で外します。自動分類はタグを足すだけで、自分で付けたタグを消すことはありません。
- ⋯ メニューの「自動分類」は、ジャンルと難易度の固定を外して分類し直します。

**ジャンルを編集する。** ナビの「ジャンル」の横の「編集」で「設定 › ジャンル」が開き、すべてのジャンルと記事数が一覧になります。名前を変えられ、別のジャンルと同じ名前にすると 2 つのジャンルを 1 つにまとめます。記事のないジャンルは削除できます。いちばん上の欄からジャンルを追加すると、自動分類はそのジャンルも選ぶようになります。

### 重要度

[「自分について」](#自分についてを書く)を書いておくと、新しく保存した記事ごとに、あなたにとってどれくらい重要かを AI プロバイダが 1〜5 で判定し、理由を 1 行付けます。5 段階は「関係なし」「少し関係」「関心あり」「重要」「必読」です。

- 記事一覧では、重要度 4 と 5 の記事に印が付きます。印にポインタを乗せると理由が出ます。Reader 表示では、タイトルの下に重要度と理由が出ます。
- ナビの「重要」には、「設定 › 重要度」の「「重要」に入れる重要度」 (既定は 4) 以上の記事が出ます。
- 判定をやめるには、「設定 › 重要度」の「新しく保存した記事の重要度を判定する」をオフにします。

**「自分について」を書き換えたとき。** それまでの判定には「(以前のプロフィールで判定)」と表示されます。判定し直すまでは、前の点数をそのまま使います。判定し直す方法は 2 つあります。

- 「設定 › 重要度」の「重要度を付け直す」: まだ判定していない記事と、以前のプロフィールで判定した記事をすべて判定し直します。
- 記事一覧の上の「重要度を付け直す」: 一覧に表示している記事を判定し直します。

### グループ

グループは、自分で選んだ記事を集めておく場所です (プロジェクトごとの資料や、読む予定の記事など)。1 つの記事を複数のグループに入れられます。

- ナビの「グループ」の「＋ 新規」で作ります。グループの ⋯ メニューで名前の変更と削除ができます。グループを削除しても、中の記事は残ります。
- 開いている記事は、Reader 表示の「＋ グループ」、パレットの「この記事をグループに追加…」、右クリックメニューの「グループに追加…」のどれかで入れます。
- 複数の記事は、一覧の上の「選択」で選んでから「グループに追加」でまとめて入れられます。
- 一括インポートで取り込む記事や、一覧でグループを開いているときに保存した URL は、保存と同時にそのグループに入れられます。

グループは、検索・対話・エクスポートの範囲としても選べます。

### 既読とお気に入り

記事を開くと既読になります。ただし、「未読」の一覧を見ているときは、一覧か絞り込みを変えるまで、開いた記事も一覧に残ります。読み進めている途中で一覧の並びがずれないようにするためです。

`m` で既読と未読を、`s` でお気に入り (星) を切り替えます。星を付けた記事は、ナビの「お気に入り」に出ます。

### 一覧・絞り込み・並び順

記事一覧には、ナビで選んだ一覧の記事を、絞り込みの条件で絞ったものが出ます。

**ナビの一覧。** 上から「最近追加」 (7 日以内に保存した記事)、「未読」「お気に入り」「すべての記事」「重要」、続いてグループ・ジャンル・フィードのフォルダ・フィード・「手動追加」 (フィード以外から保存した記事) です。ジャンルは最初の 6 つだけを表示し、残りはリンクを押すと表示します。

**絞り込み。** 一覧の上のチップで、「ジャンル」「タグ」「グループ」「ソース」「難易度」「重要度」「状態」の条件を足します。

- 「状態」の値は「未読」「既読」「お気に入り」「要対応」です。「要対応」は、取得か本文の抽出に失敗した記事と、本文が短い記事です。
- 同じ種類の条件の中で複数の値を選ぶと、どれかに当てはまる記事が出ます (OR)。種類の違う条件は、すべてに当てはまる記事が出ます (AND)。
- タグだけは、「すべて含む」 (AND) と「いずれか」 (OR) を選べます。
- 条件の横の件数は、今の一覧の中での件数です。
- 該当する記事がないときは、どの条件を外すと何件になるかが表示されます。

`Esc` で絞り込みを解除します。パレットからも条件を足せます ([コマンドパレット](#コマンドパレット)を参照)。

**並び順とまとめ方。** 一覧の上の「並び順とまとめ方」で、並び順を「追加日・新しい順」「追加日・古い順」「公開日・新しい順」「難易度・やさしい順」「重要度・高い順」から選びます。同じメニューで、一覧を「ソース」ごとや「ジャンル」ごとに区切って表示することもできます。

**キーボード。** `j` と `k` (または `↓` と `↑`) でカーソルを動かし、`Enter` で Reader 表示で、`Shift+Enter` で Page 表示で開きます。

### 右クリックメニュー

一覧の記事か、Reader 表示・Page 表示のタブを右クリックすると、その記事の操作のメニューが開きます。キーボードでは、メニューキーか `Shift+F10` で開きます。

メニューの項目は「お気に入り」「既読にする」「グループに追加…」「新しいタブで開く」「別ウィンドウで開く」「Page で開く」「URL をコピー」「Index から削除…」です。保存していないページのタブでは、そのページで使える項目だけが出ます。

### 複数の記事をまとめて操作する

1. 一覧の上の「選択」を押します。
2. 記事をクリックして選びます。`Shift` を押しながらクリックすると、範囲で選べます。「選択」を押さずに `Shift`+クリックしても、選択を始められます。
3. 選んだ記事を右クリックすると、選んだ記事すべてに効く操作 (お気に入り・既読と未読・「グループに追加…」) が出ます。

「選択を終了」か `Esc` で選択をやめます。

### Index から記事を削除する

⋯ メニューか右クリックメニューの「Index から削除…」を選び、確認画面で削除します。削除すると元に戻せません。

- 削除するもの: 保存した HTML・本文・要約・タグ・画像・検索用のデータと、ほかの記事が使っていない訳文
- 残るもの: 対話の回答の中の引用

フィードから取り込んだ記事を削除した場合、同じ記事をそのフィードから取り込み直すことはありません。

## 検索する・質問する

### 検索

`/` を押すと、保存した記事を検索します。Lattice の検索は、キーワードが一致する箇所を探す全文検索と、意味の近い箇所を探す意味検索を組み合わせた hybrid 検索です。意味検索のおかげで、日本語の検索語で英語の記事の該当箇所が見つかり、その逆も見つかります。原文と訳文の両方を検索します。

- 結果は、一致した箇所を記事ごとにまとめた一覧です。`j` と `k` で移動し、`Enter` でその箇所を Reader 表示で、`Shift+Enter` で Page 表示で開きます。`Esc` で記事一覧に戻ります。
- 範囲のメニューで、「最近追加」「未読」「お気に入り」「重要」、グループ、ジャンル、フィード、フォルダに絞れます。絞り込みのチップでさらに絞れます。
- 検索は常に両方の方式で行います。結果ごとに、「全文」「意味」「全文 + 意味」のどれで見つかったかが表示されます。「検索方式」の「Hybrid」「全文」「意味」で、表示する結果を一致の種類で絞れます。
- 検索している間は、ナビに最近の検索語が出ます。

**意味検索のモデル。** 意味検索は、multilingual-e5-small というモデル (約 470 MB) を手元の PC で動かします。モデルは、最初に必要になったとき (たいていは、最初の記事を検索用に処理するとき) にダウンロードします。準備ができるまでは全文検索の結果だけを表示し、結果の中にその理由を出します。

### コマンドパレット

`Ctrl+K` を押すか、タイトルバーの箱をクリックすると、パレットが開きます。文字を入力すると、記事のタイトル・タグ・ソース・ジャンル・コマンドをまとめて探します。先頭に次の文字を付けると、探すものを絞れます。

| 先頭の文字 | 探すもの |
|---|---|
| `#` | タグ |
| `@` | ソース (フィードとフォルダ) |
| `g:` | ジャンル |
| `>` | コマンドだけ |
| `?` | 保存した記事の本文 (検索) |

- `Enter` で、選んでいる項目を実行します。記事を `Ctrl`+クリックすると、新しいタブで開きます。
- `Tab` で、選んでいるタグ・ソース・ジャンルを一覧の絞り込みに足します。パレットは開いたままなので、続けていくつも足せます。
- `Ctrl+Enter` で、入力した語で検索します。
- URL を貼ると、「Page で開く」「Index に追加 (取り込み)」「フィードを検出して登録」が出ます ([URL を保存する](#url-を保存する)を参照)。

コマンドには、一覧の切り替えのほか、次のようなものがあります。

- 「表示言語: 混在」 (`70` のように数字を続けると、訳文の割合も指定できます)、「表示言語: 原文」「表示言語: 訳文」
- 「この記事を翻訳 (job を積む)」
- 「今日の復習を開く」「単語帳を開く」「処理状況を開く」「対話を開く」「フィードを管理」「設定を開く」
- 「一括インポート」「Markdown を取り込む」「PDF (論文) を取り込む」
- 「失敗したジョブをすべて再実行」

### 保存した記事に質問する

ナビの「対話」で対話ペインを開き、質問を入力して `Ctrl+Enter` で送ります。AI は保存した記事の内容だけをもとに答えます。回答の中の番号は引用で、押すとその根拠の箇所が開きます。範囲の記事に関係する内容がなければ、推測で答えずに、見つからなかったと答えます。

**範囲。** 「範囲」で、回答のもとにする記事を選びます。

- 「この記事」: フォーカスのあるタブの記事
- 「開いている記事すべて」: すべてのウィンドウのタブで開いている、保存済みの記事 (その下で 1 件ずつ選ぶこともできます)
- 「全記事」、今の一覧、グループ、ジャンル、フィード、フォルダ、タグ

**送る量。** 範囲の記事の本文がすべて収まるなら、全文を AI に送ります。収まらないときは、検索で質問との関係が深い箇所を選んで送ります。このとき、まず 1 記事あたり 4 箇所までにして、できるだけ多くの記事から集めます。まだ余裕があれば、同じ記事からさらに箇所を足します。回答には、全文と抜粋のどちらで答えたかが表示されます。

1 回の質問で送る量の上限は、「設定 › 要約・対話」の「対話で使う範囲」で選びます: 「少なめ (約 4 万字)」「標準 (約 8 万字)」「多め (約 15 万字)」。多いほど多くの記事を踏まえて答えますが、1 回の費用と待ち時間が増えます。

**会話。**

- 続けて質問すると、直前の 3 往復のやりとりも踏まえて答えます。
- 会話は保存されます。会話の題名のメニューから、保存した会話を開いたり、「新しい会話」を始めたり、「この会話を削除」したりできます。
- Reader 表示の「質問」を押すと、その記事について対話を始めます。
- 対話ペインの「別ウィンドウで開く」で、対話を別のウィンドウに移せます ([タブを別ウィンドウで開く](#タブを別ウィンドウで開く)を参照)。

**対話の設定。** 「設定 › 要約・対話」にあります。

| 設定 | 内容 |
|---|---|
| 「対話の追加の指示」 | 対話の回答だけに足す指示です。次の質問から効きます。 |
| 「対話で使う範囲」 | 1 回の質問で送る量の上限です。上の説明を参照してください。 |
| 「質問の入力欄で Vim キーバインドを使う」 | 入力欄で Vim のキー操作を使います。挿入モードで始まり、`Esc` でノーマルモードになります。送信はどちらのモードでも `Ctrl+Enter` です。この PC だけの設定です。 |

## 読んだ内容を身につける

### 理解度チェック

Reader 表示か Page 表示のツールバーの「理解度チェック」を押すと、記事の横にパネルが開きます。「クイズを作成」を押すと、AI が記事の要点を確かめる問題を 3〜8 問作ります。問題には、記述式と 4 択があります。

1. 4 択の問題では、選択肢を選びます。記述式の問題では、答えを頭の中で考えてから「答えを見る」を押します。「自分の答え」の欄に書いてもかまいません (書いた内容は保存しません)。
2. 答え・解説・出典を読みます。出典を押すと、本文のその箇所に移ります。
3. 「もう一度」「難しい」「正解」「簡単」から自己評価を選びます。`1`〜`4` のキーでも選べます。4 択では、正解したかどうかに合わせた評価があらかじめ選ばれています。変えることもできます。

最後まで答えたら、「復習に追加」で問題を[今日の復習](#今日の復習)に入れられます。このとき、今回の自己評価を 1 回目の復習として記録します。

- 「もう一度解く」で、最初からやり直せます。
- 記事の本文か「自分について」が変わったら、「作り直す」で新しい問題を作れます。
- パネルの状態は、別の画面やタブに移って戻ってきても残ります。Lattice を終了すると消えます。

### メモ

Reader 表示か Page 表示のツールバーの「メモ」を押すと、記事の横にメモの欄が開きます。記事ごとに 1 つ、自由に書けます。入力を止めると自動で保存し、欄の上に「保存しました」と出ます。

- メモのある記事は、ツールバーの「メモ」が強調されます。
- メモの欄と理解度チェックは同じ場所に開きます。片方を開くと、もう片方は閉じます。
- メモは JSON エクスポートとバックアップに入ります。メモを空にすると消えます。

### 単語を登録する

知らない英単語や熟語は、Reader 表示で選択して「単語を登録」を押すか、`w` を押すと登録できます。Page 表示では、文字を選択するとページの上に同じボタンが出ます。単語は、それが出てきた文と記事と一緒に保存します。

登録した後、AI プロバイダが見出し語・品詞・英語の定義・例文・発音記号 (IPA)・日本語の意味を付けます。同じ語の変化形は 1 つの項目にまとめます。たとえば、run を登録した後で ran を登録すると、新しい項目は作らず、run の項目に ran の文を足します。

登録した語は、Reader 表示の本文の中で下線付きで表示され、ポインタを乗せると意味が出ます。

登録できるのは、英字を含み、改行をまたがない、64 文字までの語句です。

### 単語帳

「ツール」の「単語帳」に、登録した語の一覧があります。

- 「単語・意味で検索」で絞り込み、「追加が新しい順」か「復習の期限が近い順」で並べ替えます。
- 語ごとの ⋯ メニューには、「意味を編集」「出典へ」「意味と例文を再生成」「復習を停止」 (停止中は「復習を再開」) 「削除」があります。意味の取得に失敗した語には「意味をもう一度取得」が出ます。
- 「記事中の登録語に下線を引く」で、本文の中の下線の表示を切り替えます。この PC だけの設定です。
- 「CSV に書き出す」で、Anki に読み込める CSV (表・裏・タグの 3 列) を `exports` フォルダに書き出します。

### 今日の復習

理解度チェックの問題と登録した単語を、カードとして 1 枚ずつ出題します。出題の間隔は、Anki と同じ SM-2 という方式で決めます。正解するたびに間隔が伸び (1 日、6 日、その後は前の間隔の約 2.5 倍ずつ)、「もう一度」を選ぶと最短の間隔に戻ります。

ナビの「今日の復習」に、今日出題するカードの枚数が出ます。開くと、まず今日の枚数 (問題と単語の内訳と、初めて出題するカードの数) が出ます。「復習を始める」を押すと、最初のカードが出ます。

- **単語のカード。** 表に見出し語・発音記号・品詞が出て、見出し語を読み上げます。裏には、英語の意味・例文・日本語の意味・登録したときの文・「出典へ」があります。「発音を聞く」「例文を聞く」か `r` で、もう一度聞けます。読み上げは「復習を始める」を押した後に始まり、画面を開いただけでは音は出ません。
- **評価。** 評価のボタンには、それぞれを選んだ場合に次に出題される時期が表示されます。ボタンか `1`〜`4` で評価します。
- **復習から外す。** カードの ⋯ メニューで、そのカードか、その記事のカードすべてを復習から外せます。単語のカードは「この単語の復習を停止 (単語帳で再開)」で止められます。
- **終わったとき。** 復習した枚数と、次のカードが出る時期が表示されます。復習中の記事の一覧から、記事ごとに復習から外すこともできます。

日付は、PC の時計で 0 時に変わります。

読み上げには Windows に入っている英語の音声を使うので、オフラインでも動きます。英語の音声が入っていない PC では、読み上げのボタンは出ません。

**復習の設定。** 「設定 › 復習」で変えられます。

| 設定 | 既定 |
|---|---|
| 「1 日の新規カード」 | 20 枚 |
| 「1 日の復習」 | 200 枚 |
| 「最短間隔」 | 1 日。1 日より短くすると、その日のうちにもう一度出題します (Anki の学習ステップと同じ動きです)。 |
| 「最長間隔」 | 365 日 |
| 「単語カードの発音を自動で再生」 | オン。この PC だけの設定です。 |

1 日の枚数の上限は、理解度チェックのカードと単語のカードを合わせた数です。

## バックグラウンドの処理

ページの取得・描画・翻訳など、時間のかかる処理は、ジョブとしてバックグラウンドで実行します。ジョブの状況は「ツール」の「処理状況」で確認できます。失敗したジョブがあると、ナビに赤い数字で件数が出ます。

ジョブには次の種類があります。「処理状況」の画面では種類を名前で表示し、名前にポインタを乗せると、かっこの中の ID が出ます。種類ごとの ⓘ でも説明を読めます。

| ジョブ | 内容 |
|---|---|
| 「取得」 (`ingest`) | URL のページを取得して本文を取り出し、記事として保存します。 |
| 「描画」 (`render`) | 取得しただけでは本文が取れないページを、表に出ないブラウザで描画して保存し直します。 |
| 「画像」 (`images`) | 記事の画像をダウンロードして保存します。 |
| 「サイトアイコン」 (`favicon`) | フィードや記事の横に出すサイトのアイコンを取得します。 |
| 「検索 index」 (`embed`) | 意味検索のために、記事の段落を数値のベクトルに変換します。手元の PC で動きます。 |
| 「翻訳」 (`translate`) | 記事の段落を AI プロバイダで翻訳します。 |
| 「要約」 (`summarize`) | 記事の要約を作ります。 |
| 「クイズ」 (`quiz`) | 理解度チェックの問題を作ります。 |
| 「単語の意味」 (`vocab`) | 登録した単語に、意味・定義・発音・例文を付けます。 |
| 「分類」 (`classify`) | 記事にジャンル・タグ・難易度を付けます。1 回の呼び出しで最大 20 件を処理します。 |
| 「重要度」 (`relevance`) | 「自分について」をもとに記事の重要度を付けます。1 回の呼び出しで最大 20 件を処理します。 |
| 「取り込みフィルタ」 (`feed_filter`) | フィードの新着を取り込むかどうかを AI で判定します。1 回の呼び出しで最大 20 件を処理します。 |

AI プロバイダを使うジョブ、手元の PC で動くジョブ (検索 index)、ネットワークを使うジョブは、それぞれ別の順番待ちで実行します。そのため、翻訳が大量にたまっていても、記事の取り込みは待たされません。同じサイトからの取得は 1 件ずつ行うので、一括インポートで 1 つのサイトに負荷が集中することはありません。

**ジョブの状態と再試行。** ジョブの状態は「待機」「実行中」「再試行待ち」「失敗」のどれかです。

- 失敗したジョブは「再試行待ち」になり、2 分・4 分・8 分・16 分と間隔を空けて自動で再試行します。5 回試しても成功しないと「失敗」になり、止まります。
- 「今すぐ再実行」は、再試行待ちのジョブを待たずにすぐ実行します。「再実行」は、失敗したジョブをもう一度実行します。
- 「失敗を再実行」は種類ごとに、「失敗をすべて再実行」は全種類の失敗したジョブを、まとめて実行し直します。
- 「取り消し」は、再試行待ちか失敗のジョブを削除します。実行中のジョブは取り消せません。

### 画像

「画像を保存する」がオンなら、記事の画像 (PNG・JPEG・GIF・WebP・AVIF) をダウンロードしてデータベースに保存します。SVG の画像は保存せず、元の場所へのリンクのままにします。

- 「1 枚あたりの上限」は既定で 5 MB です。1〜20 MB の間で変えられます。
- 記事 1 件あたりに保存する画像は、合計 30 MB までです。
- オフにしても、保存済みの画像は消えません。

### 表示言語

メニュー・ボタン・メッセージの言語を、日本語か英語から選びます。初めて起動したときは、Windows の言語に合わせます。選ぶとすぐに切り替わり、再起動は要りません。記事を翻訳する向き (日本語の記事は英語へ、それ以外は日本語へ) は変わりません。

### ショートカット

すべてのショートカットの一覧です。

- 「+ キーを追加」を押すと、次に押したキーを記録して割り当てます。`Ctrl` などの修飾キーと組み合わせたキーも使えます。1 つの操作に複数のキーを割り当てられます。
- 同じキーが 2 つの操作に割り当てられているときは、一覧で上にある操作が優先され、警告が出ます。
- 「既定に戻す」で 1 つの操作を、「すべて既定に戻す」ですべての操作を、既定のキーに戻します。

ショートカットは、この PC だけの設定です。

### ブラウザ

「検索エンジン」は、Page 表示の URL の欄に URL 以外の語を入力したときと、ホームボタンに使います。DuckDuckGo (既定)・Google・Bing・Brave Search・Kagi・「カスタム」から選びます。「カスタム」では、検索語が入る位置に `%s` を書いた「検索 URL」を入力します。この PC だけの設定です。

### 起動・タスクバー

- 「Windows の起動時に Lattice を起動」: Windows にサインインしたときに Lattice を開きます。既定はオフです。タスク マネージャーの「スタートアップ アプリ」で Lattice を無効にすると、この設定もオフになります。
- 「未読数をタスクバーに表示」: タスクバーの Lattice のボタンに、未読の記事数を重ねて表示します。100 件以上は「99+」と表示し、0 件のときは何も表示しません。

### アップデート

「更新を確認」で、GitHub の Releases ページに新しいバージョンがあるか確認します。Lattice は起動したときにも確認し、新しいバージョンがあれば、タイトルバーの下に知らせる帯を出します。

- **インストーラー版。** 帯の「更新して再起動」で、新しいバージョンをダウンロードし、署名を確かめてからインストールして再起動します。データはそのまま残ります。「リリースノート」で変更点を読めます。「後で」で帯を閉じます。
- **ポータブル版。** 自動では更新しません。帯の「ダウンロードページ」から新しい zip をダウンロードし、中の `Lattice.exe` で今のものを置き換えてください。

| `Ctrl+Enter` | 対話の入力欄 | 質問を送信する |
| `Tab` | パレット | 選んでいる項目を絞り込みに足す |

### Web ページにフォーカスがあるとき

Page 表示の Web ページをクリックすると、キーボードの入力はそのページに送られます。その場合も、Lattice のショートカットは次の条件で効きます。

- `Ctrl+K`・`Ctrl+B` など `Ctrl` を使うショートカットは、ページの入力欄の中でも効きます。
- `j`・`s`・`v` のような 1 文字のショートカットは、ページの入力欄の外で、しかもページ自身がそのキーを使っていないときに効きます。
- `Enter`・`Esc`・矢印キー・`Space` は、ページのスクロールや操作に使われ、Lattice のショートカットとしては働きません。
- `Alt+←`・`Alt+→`・マウスの戻る・進むボタンは、ページの履歴を移動します。
- `w` と `r` はページの上では効きません。単語はページの上に出るボタンで登録します。

## CLI と MCP

`lattice-cli.exe` は、保存した記事をターミナルから検索・閲覧するためのコマンドです。MCP サーバーとして動かすと、Claude Code などの AI エージェントに記事を提供できます。

- インストーラー版・ポータブル版のどちらでも、`Lattice.exe` と同じフォルダに入っています。インストーラー版の既定の場所は `%LOCALAPPDATA%\Lattice` です。PATH には登録しないので、フルパスで実行します。
- アプリと同じデータを使います。ポータブル版の `data` フォルダや、「設定 › ログ・保存場所」で選んだフォルダも、そのまま使います。アプリを起動している間も使えます。
- ポータブル版では、展開したフォルダで `.\lattice-cli.exe` を実行します。このとき使うのは隣の `data` フォルダです。別のライブラリを使うときは `--data-dir パス` を指定します。
- 以下の例は既定の場所にインストールした場合です。別の場所にインストールしたときは、実行ファイルのパスを置き換えてください。
- Lattice の更新やアンインストールの前には、MCP クライアントを終了し、CLI が動いていない状態にしてください。

### コマンド

```powershell
& "$env:LOCALAPPDATA\Lattice\lattice-cli.exe" search "MVCC write skew" --limit 5
```

```powershell
& "$env:LOCALAPPDATA\Lattice\lattice-cli.exe" --format text get 42
```

| コマンド | 内容 |
|---|---|
| `search 検索語` | 保存した記事を hybrid 検索します。`--scope`、`--limit` (既定 20)。 |
| `get ID` | 1 つの記事のメタデータ・要約・本文を出します。`--blocks` で段落を ID 付きで、`--translation` で保存済みの訳文も出します。 |
| `list` | 保存した記事を新しい順に出します。`--scope`、`--limit` (既定 50)。 |
| `summary ID` | 記事の保存済みの要約を出します。 |
| `tags` | タグと記事数を出します。 |
| `genres` | ジャンルと記事数を出します。 |
| `feeds` | 登録したフィードと、そのフォルダを出します。 |
| `collections` | グループと、その ID・記事数を出します。 |
| `jobs` | 待機中・実行中・失敗したジョブを出します。 |
| `ask 質問` | 保存した記事をもとに、引用付きで回答します。アプリで設定した AI プロバイダを使います。`--scope`。 |
| `save URL` | URL を保存します。書き込みの許可が必要です。`--run` を付けると、アプリに任せずに CLI がその場で取得します。 |
| `tag ID 名前` | 記事にタグを付けます。書き込みの許可が必要です。 |
| `read ID` | 記事を既読にします。書き込みの許可が必要です。 |
| `favorite ID` | 記事をお気に入りにします。書き込みの許可が必要です。 |
| `mcp` | 上のコマンドを、stdio で通信する MCP サーバーとしてエージェントに提供します。 |

どのコマンドにも付けられるオプション:

- `--format json` (既定) か `--format text` (人が読みやすい形式)
- `--data-dir パス`: 別のデータフォルダを使います。
- `--allow-write`: `save`・`tag`・`read`・`favorite` を許可します。環境変数 `LATTICE_ALLOW_WRITE=1` を設定しても同じです。

コマンドの一覧は `lattice-cli --help` でも見られます。

### 範囲の指定

`--scope` には、次のどれかを指定します。

| 範囲 | 対象の記事 |
|---|---|
| `all` | すべての記事 (既定) |
| `unread` | 未読の記事 |
| `favorites` | お気に入りの記事 |
| `tag:名前` | そのタグの記事 |
| `genre:名前` | そのジャンルの記事 (`genre:none` で未分類の記事) |
| `feed:ID` | そのフィードの記事 (`feed:none` で手動で追加した記事) |
| `folder:ID` | そのフォルダに入っているフィードの記事 |
| `collection:ID` | そのグループの記事 (`group:ID` とも書けます) |
| `important` か `important:下限` | 重要度が下限以上の記事 (下限の既定は「設定 › 重要度」で選んだ値) |
| `article:ID` か `article:3,7` | 指定した記事 |

フィードの ID は `feeds` で、グループの ID は `collections` で分かります。フォルダの ID は、`--format json` のときに出ます。

### CLI でできること・できないこと

- 検索の結果はアプリと同じです。ただし、アプリがまだ意味検索のモデルをダウンロードしていないときは、CLI はモデルをダウンロードせず、全文検索だけで答えます。JSON の出力にそのことが書かれます。
- `ask` でした質問は、アプリの対話の履歴にも残ります。
- `save` は取得を順番待ちに入れるだけで、起動中のアプリが 30 秒以内に取得します。`--run` を付けると、CLI 自身がページ・画像と、(モデルがあれば) 検索用のベクトルを取得します。分類・重要度・自動翻訳・描画は、どちらの場合もアプリが行います。
- `tag`・`read`・`favorite` での変更は、アプリが次に一覧を読み直したときに画面に反映されます。
- お気に入りや既読の解除、タグの削除、記事の削除はできません。エージェントにさせる操作を、取り消しやすいものに限っているためです。

### Claude Code から使う

```powershell
claude mcp add lattice -- "$env:LOCALAPPDATA\Lattice\lattice-cli.exe" mcp
```

こう登録すると、エージェントは `search`・`get`・`list`・`summary`・`tags`・`genres`・`feeds`・`collections`・`jobs`・`ask` を tool として使えます。`save`・`tag`・`read`・`favorite` も使わせるには、`mcp` の後に `--allow-write` を付けます。

### prompt injection に注意する

保存した記事は他人が書いた Web ページです。エージェントに記事を読ませると、本文に仕込まれた指示に従ってしまうことがあります (prompt injection)。

Lattice は tool の結果の先頭に、この内容は信頼できない外部の文章であり、中の指示に従ってはならない、という注意書きを付けます。また、1 回の結果は 25,000 文字で切ります。それでも危険はなくなりません。次のことを守ってください。

- 必要なとき以外は、書き込み (`--allow-write`) を許可しないでください。
- 記事を読ませるエージェントのセッションに、シェルの実行・ファイルの書き込み・メールの送信のような危険な tool を同時に持たせないでください。

## データとバックアップ

### データの保存場所

Lattice のデータは、すべて 1 つの SQLite のデータベースファイルに入っています。記事・取得した HTML・訳文・要約・画像・検索用のデータ・対話・クイズ・単語・設定です。インストーラー版の既定の場所は次のとおりです。

| もの | 場所 |
|---|---|
| データベース | `%APPDATA%\Lattice\lattice.db` |
| バックアップ | `%APPDATA%\Lattice\backups\` |
| エクスポート (JSON・CSV・OPML) | `%APPDATA%\Lattice\exports\` |
| 意味検索のモデル | `%APPDATA%\Lattice\models\` |
| ログ | `%LOCALAPPDATA%\Lattice\logs\` |

実際に使っている場所は「設定 › ログ・保存場所」に表示されます。「フォルダを開く」で、今使っているデータフォルダを開けます。

- **ポータブル版**は、ログとアプリ内ブラウザの Cookie・キャッシュも含めて、すべてを `Lattice.exe` の隣の `data` フォルダに保存します。
- **ログ**は、データフォルダを別の場所に移しても `%LOCALAPPDATA%\Lattice\logs` に保存します (ポータブル版は `data\logs`)。
- **開発版** (ソースからビルドしたもの) は、`Lattice Dev` という別のフォルダを使います。データ・ログ・アプリ内ブラウザのログイン状態は、リリース版と共有しません。以前のテスト版が使っていたフォルダのデータは、自動では移りません。

**この PC だけに保存する設定。** 次の設定は、データベースではなく PC に保存します。そのため、バックアップに含まれず、別の PC には引き継がれません: ショートカット、検索エンジン、「表示を切り替えたら自動で翻訳」、Vim キーバインド、単語の読み上げ、登録語の下線、最近の検索、Page 表示の要約ボタン、フォルダの開閉、ウィンドウの配置。

### データフォルダを移す

「設定 › ログ・保存場所」の「変更…」で、新しいフォルダを選びます (ポータブル版にはこのボタンはありません)。

1. Lattice が、データベース・バックアップ・エクスポート・検索モデルを新しいフォルダにコピーします。API キーもデータベースと一緒にコピーされます。
2. Lattice を再起動すると、新しいフォルダを使い始めます。コピーした後に追加・変更したものは新しいフォルダに入らないので、コピーが終わったらすぐに再起動してください。
3. 元のフォルダのデータは削除しません。要らなくなったら自分で削除してください。

選んだフォルダにすでに Lattice のデータがあるときは、コピーせずに、そのデータに切り替えます。起動したときに選んだフォルダが見つからないか使えない場合は、既定の場所で起動し、設定画面にその理由を表示します。

### バックアップ

「設定 › バックアップ」の「今すぐバックアップ」で、データベースのコピーを `backups` フォルダに書き出します。「残す世代数」 (既定 30) を超えると、古いものから削除します。日数が経ったことを理由には削除しません。

バックアップには、記事・画像・訳文・単語・復習の履歴・データベースの中の設定が入ります。API キーと R2 の Secret Access Key は入りません。[この PC だけに保存する設定](#データの保存場所)も入りません。

### クラウドバックアップ (R2)

「設定 › クラウドバックアップ (R2)」で、データベースのコピーを Cloudflare R2 の bucket に定期的にアップロードできます。コピーは gzip で圧縮し、API キーは除きます。

1. Account ID・bucket・Access Key ID・Secret Access Key を入力します。
2. 「自動バックアップ」をオンにします。
3. 「間隔 (時間)」 (既定 24) と「残す世代数」 (既定 30) を決めます。

「今すぐ R2 にバックアップ」で、すぐに 1 回アップロードします。複数の PC から同じ bucket にバックアップできます。

bucket を作るための Terraform と、アクセスキーの作り方・復元の手順は [`infra/r2`](../infra/r2/README.md) にあります。

### バックアップから復元する

復元は手作業で行います。データベースのファイルを置き換えるので、作業中はそのライブラリを使うすべてのプロセス (Lattice・`lattice-cli`・MCP サーバー) を止めておいてください。動いている間にデータベースを置き換えないでください。

ローカルのバックアップは `backups/lattice-<Unix 秒>.db` という名前の SQLite ファイルで、そのまま使えるデータベースです。

1. 「設定 › ログ・保存場所」で、データベースのフルパスを控えます。データフォルダを移した場合やポータブル版でも、ここに表示されたパスを使います。
2. 復元したいバックアップを、別のフォルダにコピーします。元のバックアップには手を加えません。ファイル名が `.db.gz` で終わるときは、先に展開します。R2 からバックアップをダウンロードする方法は [R2 の復元手順](../infra/r2/README.md#3-復元)を参照してください。
3. このデータベースを使う Lattice のすべてのウィンドウ・CLI・MCP サーバーを終了します。
4. 今の `lattice.db` を、退避用のフォルダに移します。`lattice.db-wal` と `lattice.db-shm` があれば、それも一緒に移します。古い WAL・SHM ファイルを元の場所に残さないでください。
5. バックアップのデータベースを元のフォルダにコピーし、名前を `lattice.db` にします。
6. Lattice を起動し、記事・画像・訳文・単語・復習の履歴がそろっているか確認します。
7. 設定で、API キーと R2 の Secret Access Key を入力し直します。バックアップがまた動くことを確認するまで、退避したファイルは残しておいてください。

復元する前のデータベースに戻したいときも、先にそのライブラリを使うすべてのプロセスを終了します。そのうえで、復元したデータベースと、その WAL・SHM ファイルをまとめて別の場所に移し、退避しておいた元のファイル一式を戻します。

### エクスポート

「設定 › エクスポート」で、ライブラリの内容を gzip で圧縮した JSON Lines として `exports` フォルダに書き出します。ほかのツールでデータを使いたいときのための機能です。「エクスポートする範囲」で、ライブラリ全体か 1 つのグループを選びます。

- **含むもの:** 記事・段落・訳文・要約・メモ・タグ・ジャンル・フィードとフォルダ・グループ・クイズ・対話 (グループだけをエクスポートしたときは、対話は含みません)
- **含まないもの:** API キーなどの設定・登録した単語・取得した HTML・画像・検索用のベクトル

含まないものも残したいときは、[バックアップ](#バックアップ)を使ってください。登録した単語は、単語帳の「CSV に書き出す」でも書き出せます。

## プライバシーと安全

### 通信する相手

Lattice には利用状況の収集・解析やアカウントはありません。通信するのは次の相手だけです。

| 相手 | いつ |
|---|---|
| 記事を保存するサイトと、その画像・アイコンのサイト | 記事を保存したとき、登録したフィードに新しい記事が来たとき |
| 登録したフィード | 登録したとき、その後は Lattice の起動中に定期的に |
| 設定した AI プロバイダ | [AI プロバイダに送るもの](#ai-プロバイダに送るもの) の機能を使ったとき |
| Page 表示で開いたページと、選んだ検索エンジン | 開いたとき |
| Hugging Face | 意味検索のモデルを最初にダウンロードするときの 1 回 |
| 自分の Cloudflare R2 のバケット | クラウドバックアップを設定したときだけ |
| GitHub (`github.com`) | 起動時と「設定 › アップデート」で、新しいバージョンを確かめるとき (インストール版だけ)。ライブラリのデータは送りません。 |

### AI プロバイダに送るもの

Lattice が設定した AI プロバイダに文章を送るのは、次の機能を使うときだけです。

| 機能 | 送るもの |
|---|---|
| 翻訳 | 訳す段落と、翻訳の「追加の指示」 |
| Page 表示の翻訳 | 表示中のページの段落 (「混在」か「訳文」を選んでいるときだけ) |
| 要約 | 記事の本文、「自分について」、要約の追加の指示 |
| 分類 | タイトル、ドメイン、要約か本文の冒頭 |
| 重要度 | タイトル、ドメイン、要約か本文の冒頭、「自分について」 |
| 理解度チェック | 記事の本文、「自分について」 |
| 単語の意味 | 単語と、登録したときの文 |
| フィードの LLM 判定 | 新着記事のタイトル・URL・抜粋、「自分について」、取り込む記事の指示 |
| 対話 | 質問、範囲の記事の本文、直前の 3 往復、「自分について」、対話の追加の指示 |

意味検索・読み上げ・本文の抽出は、手元の PC だけで動きます。Claude CLI と Codex CLI のプロバイダは、あなたがそれぞれの CLI にログインしたアカウントを使います。

### API キー

API キーと R2 の Secret Access Key は、手元のデータベースに保存します。保存した後は画面に表示せず、バックアップ・R2 へのアップロード・エクスポートにも含めません。「設定 › ログ・保存場所」の「変更…」でデータフォルダを移すときは、データベースと一緒に新しいフォルダへコピーします。

### 記事の内容は信頼しない

保存したページは他人が書いたものです。Lattice は、記事の内容を指示としては扱わず、ただのデータとして扱います。

- 記事の本文は、文字として表示します。記事の HTML やスクリプトが、Lattice のウィンドウの中で実行されることはありません。
- Web ページは、Lattice 本体とは分けたブラウザで表示します。このブラウザは http と https のアドレスしか開けず、Lattice の機能もごく一部しか呼び出せません。
- AI プロバイダには、ファイル操作やコマンド実行などの tool を一切渡しません。Claude CLI と Codex CLI は、tool・MCP サーバー・ユーザー設定を無効にし、空の一時フォルダで実行します。どの prompt でも、記事の中の指示に従わないよう AI に指示しています。
- Page 表示のページに差し込む訳文からは、スクリプトや危険なリンクを取り除きます。

### 記事の取得先の制限

Lattice が直接 HTTP で取得するもの (記事・PDF・フィード・画像・サイトアイコン) は、既定でプライベートネットワークのアドレス (`localhost` や `192.168.x.x` など) からは取得しません。リダイレクトされた先のアドレスも確認します。

- この制限は、アプリ内ブラウザ・JS 描画・AI プロバイダ・バックアップ・意味検索モデルのダウンロードには適用しません。
- 0.1.0 には、取得してよい通信先を設定する画面はありません (以前のバージョンで保存したルールは引き続き効きます)。社内サイトなどを例外として許可する設定は、[記事取得の詳細設定](roadmap.md#記事取得の詳細設定)として計画しています。
- OS や環境変数のプロキシ設定 (プロキシを使わない宛先の設定を含む) は、そのまま使います。プロキシを経由すると、最終的な接続先の IP アドレスはプロキシが決めるので、Lattice からは確認できません。プロキシ経由の接続先を制限したいときは、プロキシ側でルールを設定してください。

## 困ったときは

### 翻訳が止まっているように見える

- 「処理状況」を開きます。翻訳のジョブが「実行中」なら、まだ処理しています。CLI のプロバイダでは、長い記事だと 1 回の呼び出しに数分かかることがあります。AI のジョブごとにかかった時間はログに記録されます。
- 「再試行待ち」のジョブは、一度失敗して、usage limit が明けるのを待つなどしています。「今すぐ再実行」で、待たずに実行できます。
- ツールバーに「残りを翻訳」が出ていれば、まだ訳していない段落があります。押して続きを訳してください。
- 日本語の記事は英語に訳します。言語の判定を誤ったわけではありません。
- 何も起きないときは、「設定 › AI プロバイダ」を確認してください。動くプロバイダの段が 1 つ以上必要です。

### 検索で全文検索の結果しか出ない

検索結果に、全文検索の結果だけを表示している理由が出ます。多くの場合、意味検索のモデルがまだダウンロード中か、ダウンロードしようとしたときにオフラインだったことが原因です。「再試行」でもう一度ダウンロードを試します。新しく保存した記事は、「検索 index」のジョブが終わると意味検索で見つかるようになります。

### ページを保存できない・本文が短い

- 「取得失敗」と出る記事は、ページをダウンロードできなかったものです。ブラウザ以外からの取得を断るサイトもあります。Page 表示で開いて「Index に追加」を押すか、保存済みの記事なら「表示中のページで取り込み直す」を選んでください。
- 「本文が短い」と出る記事は、JavaScript で描画するページかもしれません。⋯ メニューの「描画して取り込み直す」か、上の Page 表示での方法を使ってください。
- ログインが必要なサイトは、先に Page 表示でログインしておいてください。ページを描画する表に出ないブラウザも、そのログイン状態を使います。
- スキャンした画像だけの PDF には文字のデータがないので、本文を取り込めません。

詳しくは[本文がうまく取れないページ](#本文がうまく取れないページ)を参照してください。

### フィードから思ったように取り込まれない

- フィードの管理画面で、フィードごとのエラーを確認します。「すべて更新」で、すべてのフィードを今すぐ確認します。
- フィードの「編集」の中の「除外された記事」に、取り込みフィルタで除いた記事が理由と一緒に残っていないか確認します。
- 登録したばかりのフィードは、最新の 20 件だけを取り込みます。それより古い記事は取り込みません。

### Web ページの上でショートカットが効かない

キーボードの入力が Web ページに送られています。1 文字のショートカットは、ページの入力欄の外で、ページ自身がそのキーを使っていないときだけ効きます。`Ctrl+K` はいつでも効きます。ページの外 (記事一覧など) をクリックすると、キーボードの入力が Lattice に戻ります。

### タブを別のウィンドウに移したらページが読み込み直された

仕様です。タブを別のウィンドウに移すと、Web ページは読み込み直し、戻る・進むの履歴も引き継ぎません。

### Web ページの上のメニューが少し遅れて出る

Web ページの上に重なるメニューは、ページを静止画に置き換えて後ろに隠してから表示するため、少し時間がかかります。⋯ のボタンにポインタを乗せてから押すと、速く表示されます。

### 空のライブラリで起動した

選んでいたデータフォルダが見つからないか使えないと、Lattice は既定の場所で起動します。理由は「設定 › ログ・保存場所」に表示されます。フォルダの問題を直すか、「変更…」でフォルダを選び直してください。

### アップデートを確認できない

「設定 › アップデート」に自動更新が設定されていないと表示されるときは、そのビルドでは更新を確認できません。新しいバージョンは [Releases ページ](https://github.com/Maru32768/lattice/releases)から入手してください。ポータブル版は自動では更新しないので、新しい zip の `Lattice.exe` で置き換えてください。

### ログの場所

ログは `%LOCALAPPDATA%\Lattice\logs\` (ポータブル版では `data\logs`) にあります。実際の場所は「設定 › ログ・保存場所」で確認できます。ログには、失敗したジョブ・バックアップの結果・AI のジョブごとにかかった時間が記録されます。
