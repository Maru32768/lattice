# 2026-10-29 の情報アーキテクチャのレビュー

情報アーキテクチャ (IA) の定番の原則を調べてまとめ、それを観点にアプリを見直した。コードと docs を読んだだけで、実際のアプリは操作していない。2026-10-22 のレビュー (`docs/review-2026-10-22/`、roadmap の I1〜I16) で出た概念モデルの問題は繰り返さず、それと重ならない指摘を K1〜K8 として roadmap の §2 に記録した。

## 1. IA の原則のまとめ

### 枠組み

- **4 つの仕組み** (Rosenfeld・Morville・Arango『Information Architecture』): IA は組織化 (何をどの軸で分類するか)・ラベリング (何と呼ぶか)・ナビゲーション (どうたどるか)・検索 (どう探すか) からなる。
- **ファセット分類**: 互いに独立した複数の軸で分類する。1 つの階層より拡張しやすく、同じものに複数の道筋で着ける。絞り込むたびに結果が 0 件になる選択肢を除くのが定石。
- **ontology → taxonomy → choreography** (Abby Covert『How to Make Sense of Any Mess』): まず語の意味を決め、次にその語で構造を組み、最後に利用者の動きの流れを設計する。最初の段階で語がぶれると、後の 2 つも崩れる。
- **見つけやすさ** (NN/g ほか): findability (あると分かっているものに着ける) と discoverability (知らなかったものに気付ける) を分けて考える。ラベルは具体的にし、互いに重ならないようにする。同じものは常に同じ語で呼び、内部の用語は出さない。設計案は card sorting で作り、tree testing で確かめる。

### Dan Brown の 8 原則 (IA Summit 2010)

| 原則 | 要点 |
|---|---|
| Objects | 内容を、属性とライフサイクル (作る・変える・消す) を持つ「もの」として扱う |
| Choices | 選択肢を絞り、意味のあるものだけを出す |
| Disclosure | 先に何があるかを判断できるだけの情報を出し、詳細は奥に置く |
| Exemplars | カテゴリは代表例を見せて説明する |
| Front doors | 利用者の半分ほどはトップ以外から入ってくると考える |
| Multiple classification | 同じものを複数の分類で探せるようにする |
| Focused navigation | 1 つのメニューには 1 つの目的だけを持たせる。性質の違うものを混ぜない |
| Growth | 今の内容は将来のごく一部だと考えて設計する |

### レビューの観点

1. 1 つの概念に 1 つの語を使っているか
2. メニューごとに目的が 1 つか
3. 分類の軸が 1 つの画面の中で混ざっていないか
4. 主な作業に、常に見える入口があるか
5. 項目が増えても構造が崩れないか
6. 同じ種類のものを同じ方法で管理できるか
7. 位置が安定しているか

## 2. よくできている点

- 同じ記事に、ナビ・パレット (`#` `@` `g:` `?`)・検索・対話の 4 つの道筋で着ける (Multiple classification)。
- 絞り込みに件数が出て、0 件のときは「どれか 1 つを外すと何件になるか」を出す。ファセット検索の定石どおり。
- ジャンルは最初の 6 つだけを出し、残りは押すと出る (Disclosure)。戻る・進むと `Esc` で前の場所に戻れる。
- guide が「集める・読む・整理・検索と質問・身につける」という作業の単位で書かれている。

## 3. 指摘

重大度: **高** = 主な作業の入口や警告が見えない、**中** = 同じものが場所によって違う名前・違う方法で出る、**低** = 手がかりが弱い・位置がずれる。

### K1. 記事を集める入口が常には見えていない — 高 (観点 4)

`FirstRun.tsx` の 4 つの入口 (URL・フィード・一括インポート・Markdown) は、ライブラリが空のときにしか出ない。その後は次の場所に分かれる。

| 作業 | 入口 |
|---|---|
| 1 件の URL を保存する | パレットに貼る、Page 表示の「Index に追加」 |
| フィードを登録する | フィードの管理画面、パレット |
| 一括インポート | ナビの「ツール」、パレット |
| Markdown・PDF を取り込む | パレットだけ |

記事を集めるのはこのアプリの最初の作業なのに、そのための常設のボタンがない。案: ナビか一覧の見出しに「＋ 追加」を置き、FirstRun と同じ 4 つの選択肢を出す。

### K2. フィードが増えると「ツール」と「設定」が画面の外に押し出される — 高 (観点 5)

ナビは「一覧 → グループ → ジャンル → フィードのツリー (上限なし) → 手動追加 → ツール → 設定」の順に並び、`.nav` 全体がスクロールする (`App.css` の `.nav { overflow-y: auto }`)。フィードが 50 件あると、「処理状況」の失敗件数と「今日の復習」の件数はスクロールしないと見えない。警告として出しているものが見えなくなる。フィードのツリーは既定で開いていて、開閉の状態は保存しない (`Nav.tsx` の `useState(true)`)。案: ツールと設定を下端に固定するか、上限のない一覧より上に移す。開閉の状態を保存する。

### K3. ナビの「ツール」に性質の違う 4 種類が混ざっている — 中 (観点 2)

「ツール」には、ペインの開閉 (対話、`aria-pressed`)・学習の画面 (今日の復習・単語帳)・システムの状態 (処理状況)・集める操作 (一括インポート) が並ぶ。「ツール」は何でも入る名前なので、中に何があるかの手がかり (information scent) にならない。guide の作業の分け方とも合っていない。案: 「学ぶ」(復習・単語帳) の見出しを作る。対話は guide で検索と対にしているのに合わせて検索の近くに置く。処理状況は失敗数の表示として下部に置く。一括インポートは K1 の「追加」に入れる。K2 と同じ場所を変えるので一緒に直す。

### K4. 「ライブラリ」と「Index」が同じものを指している — 中 (観点 1)

保存した記事の集まりを、画面によって「ライブラリ」と「Index」で呼ぶ (「Index に追加」「Index から削除…」「貼り付けて Index」)。「ライブラリ」自体も、保存した記事全体・メインの画面 (「ライブラリに戻る」)・ナビの先頭 5 項目の見出し・設定のグループ名の 4 つの意味で使う。案: 保存した記事全体を「ライブラリ」に統一し、「Index に追加」は「ライブラリに保存」にする。ナビの見出しと設定のグループには別の語を使う。I8 の用語表に加える。

### K5. ラベルから中身が分からない、呼び名が揺れている — 低 (観点 1)

- 「最近追加」が 7 日以内であることが画面に出ない。
- 「要対応」の中身 (取得失敗・抽出失敗・本文が短い) が画面から分からない。
- 画面は「処理状況」なのに、コマンドでは「ジョブ」と呼ぶ (「この記事を翻訳 (ジョブに追加)」「失敗したジョブをすべて再実行」)。
- 日本語の UI に Reader・Page・Index・Hybrid という英語が混ざる。機能名として残すなら、用語表に理由を書く。

K4 と同じく語を決める作業なので一緒に直す。

### K6. 分類の管理方法が種類ごとに違う — 中 (観点 6)

| 分類 | 管理の方法 |
|---|---|
| グループ | ナビの行の ⋯ メニュー |
| ジャンル | ナビの「編集」で 設定 › ジャンル を開く |
| フィード・フォルダ | ナビの「管理」で専用の画面を開く (設定にも「フィード →」がある) |
| タグ | 管理する画面がない (I3) |

同じ種類の操作なのに、ボタンの名前が「編集」と「管理」で違う。取り込みフィルタも、全体は 設定 › 取り込みフィルタ、フィードごとはフィードの管理画面と 2 か所に分かれる。案: 各見出しに同じ名前の「管理」を置き、改名・統合・削除・件数を扱う同じ形の画面を開く (2026-10-22 のレビューの案 (b) と同じ方向)。

### K7. 設定の分け方の軸が混ざっている — 中 (観点 3)

- グループ「AI」は技術で分け、ほかのグループは機能で分ける。読むための機能である翻訳が「AI」に入る。復習の設定は「ライブラリ」にあるが、ナビでは「ツール」にある。
- 「自分について」は重要度・理解度チェック・取り込みフィルタにも効くが、「要約・対話」の中にある。そのため guide で別に説明している。
- パレットから設定の各セクションを直接開けない (「設定を開く」だけ)。

案: guide の作業の分け方に合わせて並べ直す。「自分について」は独立したセクションにする。パレットから各セクションを開けるようにする。

### K8. 検索している間だけ、ナビの途中に「最近の検索」が入る — 低 (観点 7)

「最近の検索」はジャンルとソースの間に出る (`Nav.tsx`)。検索を始めるとソースのツリーが下にずれる。案: 検索欄の側に置く。

## 4. 直す順番

1 つずつ直し、変更を報告してレビューを受け、問題がなくなったらコミットしてから次に進む。

| 順 | 項目 | 理由 |
|---|---|---|
| 1 | K1 | 変更が小さく、効果が大きい |
| 2 | K2 + K3 | どちらもナビの並びと下部を変える |
| 3 | K8 | ナビの残り |
| 4 | K4 + K5 | 語を決める作業。I8 の用語表と一緒に決める |
| 5 | K6 | I3 (タグの管理) と関わる |
| 6 | K7 | 設定の構造を作り直す。K3・K6 の結果に合わせる |
