## 横断した原因

レビュー 2（使ってみた結果、R1〜R6）とレビュー 3（モデルの照合、D1〜D13）は別の方法で調べたが、同じ原因に行き着いたものが多い。

| 原因 | 根拠 | roadmap |
|---|---|---|
| **「範囲」が画面ごとに別物。** 一覧は scope ∧ facet をクライアントで絞る。検索は scope だけで上位 30 件を取り、facet で後から削るので、該当があっても 0 件になりうる。対話と CLI は scope だけを受け取る。`recent` と `important` の閾値は backend に存在しない。 | D1, D4, D7, D12, D13 | I1 |
| **「Source」が出所ではない。** 実体は `articles.feed_id` 1 本で、手動・一括・Page・ファイル・CLI・削除済み feed がすべて「Added by hand」になる。feed は M:N で記事を載せるのに、記事は高々 1 つの feed に属する。手動で保存した記事は、後から同じ URL を載せた feed に黙って移る。 | D2, D3, D10 | I2 |
| **記事の処理状態のモデルが 1 つでない。** 取得失敗は記事の属性にだけ残り、LLM の失敗は Jobs にだけ出る。翻訳の件数は一覧と Reader で違い、Retry now を押しても表示が変わらない。 | R1, 1-1, 2-9 | I4 |
| **AI プロバイダが使える状態かを、画面がどこにも示さない。** 既定は Claude CLI で黙って動くのに、空状態は「設定してください」と言う。キーなしで保存でき、失敗して初めて分かる。 | R2, 1-15 | I5 |
| **入力をどう扱ったか（受け付けた・捨てた・読み替えた）を返す形が画面ごとに違う。** 不正な URL が検索に化ける。一括取り込みで行が黙って消える。エラーが入力欄から離れた場所に出る。下書きが残るかどうかが画面ごとに違う。 | R3 | I6 |
| **言語が 4 層ある。** 表示言語、訳す方向、回答・要約の言語（日本語固定）、表示モード（Reader と Page で既定が違う）が独立に決まり、合わさった結果を画面が説明しない。 | R4, 1-11 | I7 |
| **用語の出所が 3 系統ある。** i18n カタログ、backend の `msg!`、外部データ（`<title>`、OS エラー）。同じものが group / Collection / グループ、ingest / Fetch と別の名前で出る。 | R5, D6, D11, 1-6 | I8（局所分は修正済み） |
| **ペインの幅と、狭いときにどれを畳むかが決まっていない。** | R6 | I9 |
| **Tag には「誰が付けたか」の記録がない。** ユーザーが消した自動タグが、再分類で戻ってくる。 | D5 | I3 |
