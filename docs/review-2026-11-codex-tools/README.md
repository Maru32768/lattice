# Codex CLIのtoolの締め出しのレビュー記録

Codex CLI 0.164.0は、Latticeがtool featureを無効にしていても、モデルに`clock.sleep`と`collaboration.*`(サブエージェントの起動など)を見せていた。`clock.sleep`は、無効にする一覧になかった`sleep_tool` feature(既定でオン)から来ていた。`collaboration.*`は、feature flagと関係なくcode modeとサブエージェントを有効にするmodel catalogから来ていた。修正(`crates/lattice-core/src/codex.rs`)のあと、サブエージェントが次の2つのスキルでレビューし、指摘が出る間は繰り返す。

- `code-review`: 正しさのバグ
- `ponytail:ponytail-review`: ロジック・安全性・負荷・テスト・要らないコード

この記録は、指摘を人手で見なくても検出できる仕組みを作るときの材料にする。列は[review-2026-11-mobile](../review-2026-11-mobile/README.md)と同じ。

## 傾向

- 指摘数は1回目が9件(中2・低7)、2回目が12件(すべて低。うち2件は同じ指摘)。2回目のうち4件は、テストの方法が届かない範囲を説明に書くだけにした(`deferred`)。
- 1回目の9件のうち5件は、新しく足したテストが本当に確かめたいものを見ていないという指摘だった(既定のモデルだけ、使われないcatalog、名前の読み落とし、見えない種類のtool)。外部のCLIの出力を読むテストは、入力を変えると結果が変わることを一度は確かめないと、何も見ていなくても通る。
- 2件はCodexの版の違いから来ていた。`--disable`は知らない名前で失敗する。`-c`は、最上位と`features.`の下では知らないキーを黙って無視するが、`agents.`の下では役割として読むので失敗する。どちらの形で渡すかで、古い版で壊れるか、新しい版で黙って効かなくなるかが決まる。2回目のレビューでは、1回目の修正の1つがこの区別を取り違えていた。
